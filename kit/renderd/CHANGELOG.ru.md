# Изменения mgu-render

Перевод новых записей. Полная история на английском: [CHANGELOG.md](CHANGELOG.md).

## idrive7-apps mgu-renderd 2.1.7

- Входной буфер больше не растёт без ограничения, когда приложение отправляет данные быстрее, чем рендер их читает: после каждого чтения обрабатываются целые сообщения, одновременно хранится не более одного получаемого сообщения (24 МиБ плюс 128 КиБ), и при каждом пробуждении считывается примерно столько же от каждого приложения. Поэтому одно активное приложение не задерживает остальные. При ошибке выделения памяти соединение этого приложения закрывается, а не приводит к сбою всего рендера.
- Градиенты: строка градиента освобождается вместе с ресурсами приложения (при изменении размера или отключении). Раньше строки выдавались по кольцу из 256, общему для всех приложений, поэтому после достаточного числа градиентов одно приложение могло занять строку другого и нарисовать её своими цветами. Превышение лимитов (64 на приложение, 256 строк на все приложения) теперь вызывает ERROR и записывается в журнал. Новая строка без цветов очищается, а не сохраняет цвета прежнего владельца.
- Foreground gate: при ошибке pipe или fork открытые каналы закрываются, а неудачный fork больше не оставляет pid -1, которому остановка gate могла бы отправить сигнал всем процессам.
- `js/mgu_render_client.js`: PLACE только с изменением масштаба сохраняет изображения, атласы и градиенты, как и сам рендер (раньше они загружались повторно, и после 64 изображений новые отклонялись). После повторного подключения сообщение, обрезанное старым соединением, больше не блокирует сообщения нового.
- Тесты: test_gate, test_client_read, test_ramp, test_client_place и test_client_reconnect в `make test`.
